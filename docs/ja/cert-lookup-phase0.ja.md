# cert-lookup 段階 0 の実測

> 実施: 2026-11-07。利用者の無料キー（SSLMate Small・Validin Community）。
> 照会したのは組織のドメインと公開の見本（`example.com`・`google.com`・`cloudflare.com`）と、
> 存在しない名前だけ。調査対象には触れていない。生の応答は開発機の作業領域に残し、リポジトリには
> 入れない（大きく、第三者の証明書の名前を大量に含むため）。

Validin の消費: RFP 前の 2 回を含め開発全体で 7 回（予算 15 回）。

## SSLMate CT Search API

| 観測 | 結果 | 設計への影響 |
|---|---|---|
| 1 ページの件数 | **100 件** | ページ上限は件数で考える |
| 次のページ | **1 ページごとに 1 回と数える**（残り 95 → 94） | 発行が N 件のドメインは ceil(N/100) 回、終わりを空ページで確かめるなら＋1 回 |
| 空の答え | 空の配列も 1 回と数える。`Retry-After: 3600`、`Cache-Control: max-age=900` が付く | 空の確認も回数を使う |
| 並び順 | 古く見つけた順（google.com の 1 ページ目は 8 月〜10 月初め、2 ページ目は 10 月 5 日〜20 日） | RFP どおり、打ち切ると新しい側が欠ける |
| 応答量 | google.com の 1 ページ（100 件・名前込み）が **540〜608 KB** | 大きなドメインは MCP の 128 KB に収まらない。間引きは必須 |
| `match_wildcards` | `foo.nlink.jp` は無しで 0 件、有りで `*.nlink.jp` の証明書が返る | 単一ホストで有効にする設計で正しい |
| **公開サフィックス** | **`com` も `co.jp` も 200 で空の配列**（`invalid_value` にならない） | RFP の「SSLMate が断る」は誤り。空の答えを「発行が無い」と読ませない |
| 誤ったキー | 401 `{"code":"bad_credentials","message":"The provided API key (…_********) is not recognized…"}` — **本文にキーの先頭部分が載る** | 上流のメッセージをそのまま出さない。`code` から自前の文に置き換える |
| 回数超過 | サブドメイン込みを 11 回目で 429 `{"code":"rate_limited",…}`、**`Retry-After: 264`（秒）**。枠は少しずつ回復する（1 時間ごとの一斉リセットではない） | `rate_limited` に再試行までの秒数を添える |
| 残り回数 | 単一ホストは `X-Ratelimit-Limit: 100`、サブドメイン込みは `10` — 照会の種類ごとの枠がヘッダーに出る | `cache_status` は種類別に出す |
| 発行元 DN | `C=US, O=Google Trust Services, CN=WE2`（カンマ区切り） | Validin と書き方が違う → 要素で比べる |
| RSA と ECDSA | cloudflare.com: 同じ期間・同じ名前の 2 枚は**別の中間証明書**（YR1/YE2、WR1/WE1）。同じ期間・名前・発行元の組は 12 件中 0 | 発行元を含む組でまとめれば取り違えない |
| `Cache-Control` | 結果ありは `max-age=14400`（google.com は `86400`）、空は `900` | キャッシュ 4 時間は妥当。空は短く |

## Validin

| 観測 | 結果 | 設計への影響 |
|---|---|---|
| 誤ったキー | 403 `{"error":"Unauthorized user"}`。**回数を消費しない** | `upstream_error` ではなく設定の誤りとして返す |
| 存在しない名前 | 200、`status: "finished"`、0 件、`limited: false`。**1 回と数える** | 空も回数を使う。`finished` の 0 件はキャッシュしてよい |
| ワイルドカード | `*.nlink.jp` で覆われる `zz9q7-cert-lookup.nlink.jp` を照会して **0 件** | Validin は単一ホストの照会でワイルドカード証明書を返さない。履歴にそれが含まれないことを `notes` に書く |
| 通し番号 | 応答に無い（`details` は `domains`・`fingerprint`・`fingerprint_sha256` だけ） | まとめ方 3 は代わりの組（発行元・期間・名前）を使う |
| 発行元 DN | `cert_issuer: "/C=US/O=Google Trust Services/CN=WR2"`（スラッシュ区切り）と `issuer: {C, O, CN}` | `issuer` の要素を使い、SSLMate の DN を要素に分解して比べる |
| **既定の観測期間** | google.com を期間指定なしで照会 → 125 件、最初の観測は **2026-08 と 2026-11 だけ**（9・10 月が無い）、`limited: false` | 期間を指定しないと直近の一部しか返らない |
| 期間を明示 | 2025 年を指定 → 112 件（2 月〜12 月 1 日、月ごとに大きく偏る）。`lookback=1095` → 85 件（2025-02〜2026-11 に点在） | **`limited: false` でも全件とは限らない**。大きなドメインでは Validin の履歴は「標本」 |
| 小さなドメイン | 組織のドメイン（8 枚）は期間指定なしで 2024-06 以降の全発行が返った（RFP 前の実測） | 発行の少ないドメイン — 不審なドメインの多く — では、索引の深さの範囲で欠けなく返る見込み |
| `Cache-Control` | 証明書の応答に `no-store` | RFP に記載済みの扱い（手元のキャッシュは §4(c) の範囲で持つ） |

## 結論（RFP への反映）

1. 公開サフィックスは SSLMate が空で答えるので、**空の答えには「SSLMate に有効期限内の証明書が無い（公開サフィックスや索引に無い名前も空になる）」と書き、発行が無いとは言わない**
2. 上流のエラーメッセージは出さず、`code` から自前の文を作る（キーの先頭部分が載るため）
3. `rate_limited` には `Retry-After` の秒数を添える。`cache_status` の残りは照会の種類別
4. Validin の履歴は**完全さを主張しない**。期間は常に `lookback=1095` を明示して過去側を狙い、答えには
   Validin が返した観測の範囲（最初と最後の観測日）と「Validin は一部だけを返すことがある」を書く
5. Validin の単一ホストの履歴は、覆うワイルドカード証明書を含まない（`notes` で明示）
6. まとめ方 3 は通し番号を使えないので、発行元の要素（C・O・CN）・`not_before`・`not_after`・名前の集合の組を使う

利用者の判断が要るもの:

- **Validin の履歴が標本でしかないこと**（大きなドメインで月ごとに抜ける）を受け入れて進めるか
- **SSLMate の最後のページ**: 文書どおり空のページまで進むと、どのドメインも 1 回余計にかかる（単一ホストで
  1 時間 50 件、サブドメイン込みで 5 件）。100 件未満のページを最後とみなせば回数は半分だが、文書に無い前提になる
